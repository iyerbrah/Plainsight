How an answer is made

  1. The model writes one query

    It gets your question, written notes about the tables and their traps, and six worked examples. If the data can't answer the question, it says so instead of guessing.

  2. Code checks it

    The query is parsed, and anything other than a single SELECT is refused before it reaches the database.

  3. It runs read-only

    The database is opened read-only, can't read files or web addresses, and stops after 15 seconds or 1,000 rows.

  4. One second try

    If the query fails, the error goes back to the model once for a fix. You always see the SQL that produced the answer.
